# Правила репозитория 1ma

Репозиторий — монорепо плагинов bb. Ядро bb не форкается (ADR-0001). Читай
`docs/adr/` перед архитектурными изменениями и `docs/plan/` перед новой работой.

## Плагины

- Один плагин — один каталог `plugins/<id>/` со своим `package.json`,
  `tsconfig.json`, `README.md`, `PLUGIN_OVERVIEW.md` и тестами рядом с кодом.
- Зависимости плагина только из npm, без `workspace:`. bb ставит плагин из git
  обычным `npm install --omit=dev --ignore-scripts` в его каталоге.
- Новые плагины получают id с префиксом `1ma-` (`bb-plugin-1ma-<имя>`).
  Переименование меняет id и ломает установленные копии.
- Используй только публичный `@get-bb/plugin-sdk`. Копия встроенного плагина bb
  хранит `UPSTREAM.md` с коммитом и датой; не смешивай свои правки с
  переносом апстрима в одном коммите.
- Секреты только на сервере плагина; фронтенд-параметры и сохранённые значения
  считаются недоверенным вводом; вывод CLI и инструментов агента ограничен.
- Каждый сервис, расписание, слушатель и content script освобождается в dispose.

## Качество

- Перед коммитом: `pnpm run check` (marketplace, lint, format, typecheck, test)
  и `pnpm run build`. Тяжёлые команды на рабочей станции владельца идут через
  `~/.claude/bin/heavy`.
- Тесты пишутся на `@get-bb/plugin-sdk/testing`; проверяй правдоподобные
  сбои, а не обвязку. Тест засчитывается, когда его видели красным.
- Без комментариев-пересказов кода; типы на границах, `unknown` и `as`
  только там, где иначе нельзя.
- Пользовательские тексты интерфейса по-русски, идентификаторы и коммиты
  по-английски.

## Релизы

- Теги `<plugin-id>/vX.Y.Z`; `marketplace/marketplace.json` ссылается на
  диапазоны; `engines.bb` и `engines.bbPluginSdk` честные.
- Версия bb для разработки закреплена в корневом `package.json`
  (`devDependencies.bb-app`); обновление bb — отдельный коммит с прогоном CI.

## Границы сборки плагина

- Фронтенд (`app.tsx` и всё, что он импортирует) берёт из SDK только
  `@get-bb/plugin-sdk/app` и типы (`import type`). Корень
  `@get-bb/plugin-sdk` в бандл приложения не подшивается: при установке из git
  bb ставит зависимости без dev, и сборка падает. Общий контракт RPC для
  фронтенда описывается литералом `satisfies Record<string, PluginRpcMethodContract>`.
- `pnpm run check:git-install` повторяет установку bb из git для каждого
  плагина; он обязателен перед тегом релиза.

## Бренд

- Во всём своём коде и текстах продукт называется 1ma (ADR-0003). Слово bb
  остаётся только там, где речь о самом bb как основе, о его CLI или сервисах.

## Выкладка на Linux-сервер владельца

- Плагины на этот сервер выкладываются только командой
  `node scripts/release-linux.mjs` после зелёного CI на `main`. Установки из
  git и из маркетплейса здесь не используются: сервер bb ставит их зависимости
  и собирает бандлы вне лимита heavy.

## 1ma Desktop

- Код bb в репозиторий не копируется: только `desktop/upstream.json`,
  серия правок `desktop/patches/` и подмена ассетов (ADR-0004).
- Правки делаются в дереве, подготовленном `desktop/scripts/prepare.mjs`, и
  выгружаются `git format-patch`. Патчи руками не редактируются.
- Каждая правка сохраняет тесты bb зелёными; тесты на изменённое поведение
  правятся в той же правке, а не отключаются.
- Сборка самого bb на рабочей станции владельца не помещается в лимит heavy;
  она идёт только в GitHub Actions.
