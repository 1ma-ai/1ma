# ADR-0006. Суперагент: один плагин управления и сверка состояния

Статус: черновик 2026-11-14

## Контекст

Владелец поручает работу агентам на двух серверах 1ma: основной сервер на
Mac и сервер на Linux, где работает Claude. Сейчас задачи между чатами и
машинами пересылаются вручную, а долгоживущий чат-координатор одновременно
держит очередь, состояние и ревью; он растёт, упирается в лимиты и требует
напоминаний.

Сервер Linux не должен получать доступ к Mac: API сервера 1ma не имеет
аутентификации, и подключение Linux как машины сервера Mac или через bb
Connect даёт агенту на Linux полный доступ к Mac. Поэтому серверов два, и
все запросы между ними начинает Mac.

Проверки этапа 0 (на временных серверах 1ma 0.49.1 и по исходникам bb):

- Встроенный плагин Tasks хранит задачи, статусы, метки и комментарии в
  `plugins/tasks/data.db`; эти данные попадают в `bb server export`. Его RPC
  вызывается без CLI, но не объявлен как публичный контракт (`bb plugin rpc
inspect tasks`: «No discoverable RPC methods»).
- Tasks привязывает только чаты своего сервера: чат другого сервера
  отвергается («Thread not found»). Показ PR идёт через привязанный чат,
  поэтому для исполнителя на другом сервере Tasks PR не покажет.
- Tasks не реагирует на архивацию чата, а удалённый чат помечает как
  завершённый («final message posted»).
- API сервера позволяет создать чат с `origin: "plugin"`, `originPluginId` и
  `pluginMetadata` и потом найти его по `originPluginId` и пакетному чтению
  метаданных. Чат создаётся, даже если клиент не дождался ответа. Ключа
  идемпотентности у создания нет.
- `POST /threads/:id/stop` прерывает ход, но очередь сообщений чата
  остаётся.

## Решение

1. **Одно место управления.** Управляет плагин `1ma-superagent` на сервере
   Mac. В цикле управления нет модели: модель нужна только для разговора с
   владельцем, самой работы и ревью.
2. **Сверка вместо очереди событий.** Раз в минуту плагин для каждой активной
   задачи читает фактическое состояние (чат исполнителя, головной коммит PR,
   сводку ревью, метки), сравнивает с записью и делает один следующий шаг.
   Журнала событий, ключей повторов и очереди исходящих нет: пропущенное или
   повторённое событие увидит следующий проход.
3. **Учёт задач.** Запись задачи для владельца (статус, метки, комментарии,
   карточка в интерфейсе) ведёт Tasks на сервере управления. То, чего Tasks
   не умеет, плагин хранит в одной своей таблице назначений: задача → сервер,
   чат, исполнитель, PR, обработанный головной коммит. У каждого факта один
   владелец: статус — Tasks, назначение и состояние ревью — плагин. Вызовы RPC
   Tasks проходят через один модуль плагина и проверяются контрактным тестом
   на закреплённой версии bb, потому что этот RPC не публичный.
4. **Граница между серверами.** Плагин на Mac обращается к серверу Linux
   только по его HTTP API `/api/v1`; сервер Linux к Mac не обращается.
   Каждый чат исполнителя создаётся с `originPluginId: "1ma-superagent"` и
   меткой задачи в `pluginMetadata`. Перед созданием плагин ищет уже
   созданный чат по этой метке, архивные включительно, и второго не
   создаёт. Метаданные может изменить любой клиент, поэтому они служат только
   для восстановления после потерянного ответа; источник истины — таблица
   назначений. Текст из чатов Linux для плагина и бота — данные, а не
   поручение.
5. **Остановка задачи** — удаление очереди сообщений чата и затем `stop`.
6. **Сквозные проверки в GitHub Actions.** На рабочей станции владельца
   сервер 1ma и все процессы агентов делят одну группу памяти в 3 ГиБ; два
   временных сервера довели её до лимита, и ядро убивало процессы агентов.
   Поэтому проверки на живых серверах (два сервера, плагин, сценарии отказов)
   идут только в GitHub Actions, а не на рабочей станции.

## Последствия

- Владелец видит задачи в штатном интерфейсе Tasks, а ход работы — в чатах
  исполнителей. Своя лента активности не пишется.
- Выпуск bb может изменить RPC Tasks без предупреждения; контрактный тест это
  ловит до установки. Если Tasks перестанет подходить, запись задачи уходит во
  вторую таблицу плагина, назначения не меняются.
- Отклонено: Tasks как единственный учёт (не видит чатов другого сервера),
  подключение Linux машиной сервера Mac (снимает изоляцию), долгоживущий
  чат-координатор и мост через комментарии GitHub (очередь и состояние в
  контексте модели).
