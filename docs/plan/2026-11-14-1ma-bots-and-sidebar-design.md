## Что изучено

- **Grok.** Custom Agents (март 2026): до четырёх агентов, у каждого имя,
  характер и инструкции до 4 000 символов, инструменты и файлы знаний.
  Grok Bot (бета с августа 2026): бот с именем, работой, аватаром и
  профилем; память своя у каждого бота; библиотека навыков общая для всех
  ботов; расписания (routines) у каждого бота свои; подключённые приложения
  общие; боты общаются сообщениями и через общие файлы, общей памяти нет.
  Отсюда устройство бота: личность и инструкции, своя память, общие навыки
  и инструменты, свои расписания.
- **Bots Sidebar 1.1.0** (`ff58530`, без лицензии; повторяем вид и
  устройство, код не берём). Заменяет весь список чатов через
  `experimental_threadList`. Бот: имя, роль, аватар, SOUL до 4 096 символов,
  память до 3 000 символов (дописывает сам агент инструментом с проверкой
  хеша), настройки нового чата, проекты. Чаты бота — дерево под ботом.
  Аватары сделаны по [bloub](https://github.com/jeremy-prt/bloub) (MIT).
- **Cursor Sidebar 0.3.5** (MIT). Тоже свой список целиком, на штатный не
  похож; для первой версии брать из него нечего.
- **1ma (bb 0.49.0, SDK 0.6.132).** Места «блок над проектами в штатном
  списке» нет. `app.slots.navPanel` даёт пункт навигации, а
  `experimental_threadList` заменяет список целиком. Штатный список чатов
  (`plugins/thread-list`) входит в список официально копируемых встроенных
  плагинов bb (`scripts/forkable-plugins.json`, `docs/forkable-plugins.md`),
  лицензия MIT. На Mac владельца выбран именно он, и Rail ставит New thread
  в шапку панели, сразу над списком.
- На Linux в базе Bots Sidebar ботов нет; боты владельца на Mac.

## Бот

- Поля: id, имя, роль (подпись под именем), внешний вид (форма, цвет,
  выражение), инструкции, память (до 3 000 символов), возможности,
  настройки нового чата (провайдер, модель, рассуждение, права, проект,
  окружение), связанные проекты, порядок, скрыт ли.
- **Возможности** — список меток (`dev`, `marketing`, `accounting` и
  любые новые). `1ma-bots` их только хранит и отдаёт; что бот умеет в
  каждой области, включают другие плагины, прочитав
  `bots.v1.forThread`. Так бот готов к любой работе без изменения
  `1ma-bots`.
- **Чаты бота.** Принадлежность хранится в таблице `1ma-bots`, это
  источник истины. Чат, начатый из бота, создаёт сервер `1ma-bots`
  (`bb.sdk.threads.spawn`), и у него `originPluginId: "1ma-bots"`. Чаты
  бота не скрываются и не заглушаются, иначе пропадут уведомления о
  вопросах.
- **Старый чат, привязанный к боту** (перетаскиванием, из шапки чата или
  импортом), получает всё, что даёт `1ma-bots`: инструкции и память бота,
  инструменты памяти, `bot_update_identity`, `bot_message`. `configure`
  `1ma-bots` читает свою таблицу синхронно и от `originPluginId` не
  зависит. Инструментов суперагента такой чат не получает: по шву
  ревизии `7eec102` суперагент выбирает их в `configure` только при
  `origin.pluginId === "1ma-bots"` и затем проверяет `bots.v1.forThread`,
  а `originPluginId` у существующего чата не меняется. Шов не меняем.
  При привязке интерфейс прямо говорит: «Чат начат не из бота: инструменты
  других плагинов для этого бота (например, действия Главного бота) в нём
  не включатся» — и предлагает «Продолжить в чате бота». Это
  `bb.sdk.threads.fork` от `1ma-bots`: новый чат с той же историей и
  `originPluginId: "1ma-bots"`, старый остаётся как был. Тот же признак
  видят `bots.v1` (поле `startedFromBot`) и строка «Бот» в шапке чата.
- **Память бота.** В инструкциях каждого чата бота. Агент читает и меняет
  её инструментами `bot_memory_read` и `bot_memory_update` (дописать
  факт, забыть факт, заменить целиком по хешу последнего чтения). Факты
  обо всех проектах по-прежнему идут во встроенный Memory.

## Плагин `1ma-bots`

- Сервер: таблицы в базе плагина, RPC `bots.v1.list`, `bots.v1.forThread`
  (`{ threadId } → { botId, capabilities } | null`, ровно как в шве), чтение и правка
  бота, список его чатов, привязка и отвязка чата, начало чата.
  `bb.agents.configure` добавляет инструкции и память бота в его чаты;
  инструменты памяти, `bot_update_identity` и `bot_message`; один навык
  `1ma-bots` о том, как вести память и писать другим ботам.
- Интерфейс: пункт навигации «Боты» со списком ботов и редактором (имя,
  роль, внешний вид, инструкции, память, возможности, настройки нового
  чата, проекты). В шапке чата — «Бот: …», чтобы привязать чат к боту
  или отвязать. Работает с любой боковой панелью.
- Сообщения между ботами и их лимит — раздел «Сообщения между ботами».

## Плагин `1ma-sidebar`

- Копия штатного `thread-list` из bb `desktop-v0.49.0` (`7b26cae`),
  снятая процедурой bb (`scripts/lib/plugin-fork.mjs`), с `UPSTREAM.md`.
  Перенос апстрима и свои правки — разными коммитами. Свои правки —
  блок ботов сверху списка и вынос чатов бота из групп проектов: чат бота
  виден только под ботом, как в Bots Sidebar (решение владельца,
  14.11.2026).
- Блок ботов: заголовок «Боты» и `+` (новый бот). Строка бота: аватар
  с индикатором работы (круг вращается, когда работает первый чат бота;
  точки — другие работающие чаты; ожидание ответа и ошибка видны
  отдельно), имя, роль, число чатов и стрелка. Раскрытый бот показывает
  дерево своих чатов, старые свёрнуты в «Ещё N». Щелчок по боту
  открывает его первый чат; `+` при наведении — новый чат с настройками
  бота; меню бота: изменить, новый чат, скрыть.
- Данные блок читает прямо из RPC `1ma-bots`: `experimental_useRpcQuery`
  принимает `pluginId` другого плагина, так что своего сервера-посредника
  у блока нет. Без `1ma-bots` блока нет, список работает как штатный.
- Выбирается в «Настройки → Внешний вид» как список чатов
  (`sidebar.threadListProvider`). Навигацию копия не регистрирует: Rail и
  New thread в шапке остаются штатными. Строки чатов, меню чата, значки
  состояния, перетаскивание и сочетания клавиш — те же компоненты копии,
  что и в штатном списке; блок ботов своих не рисует.
- **Сосуществование со встроенным `thread-list`.** Встроенный плагин не
  отключается; активен тот список, что выбран в настройке. Всё, что в
  копии названо идентификатором `thread-list`, получает идентификатор
  `1ma-sidebar`: id плагина, слот списка (`1ma-sidebar/…`), действие
  `thread-list/move`, CLI (`bb 1ma-sidebar prefs …`, имя берётся из
  `bb.pluginId`), навык (`1ma-sidebar`). Тест копии проверяет, что в
  собранном плагине не осталось регистраций с `thread-list`.
- **Настройки списка** (группировка, сортировка, свёрнутые группы,
  порядок разделов) копия хранит в своём `bb.storage.kv`, как и
  встроенный список. При первом запуске она один раз переносит их из
  встроенного (`bb.sdk.plugins.callRpc` → `thread-list`
  `listPreferences`) тем же способом, каким встроенный переносит их из
  настроек 1ma. Дальше настройки двух списков независимы.
- **Сбой.** Если данные ботов не получены (нет `1ma-bots`, ошибка или
  таймаут RPC), блок показывает строку «Боты недоступны», а группы
  проектов показывают все чаты целиком, без выноса чатов бота.
- **Скрытый бот.** Чат уходит из группы проекта, только пока он виден под
  видимым ботом. У скрытого бота чаты возвращаются в свои проекты;
  чаты в «Готово: N» видны по щелчку. Чат, где ждут ответа владельца,
  никогда не пропадает из виду.

## Что взято у OpenBot (CopilotKit)

Изучен `copilotkit/openbot` на коммите `039d4fe` (14.11.2026, MIT;
серверного кода в репозитории нет, только приложение, контракты OpenAPI и
документация; слой памяти Intelligence под отдельной лицензией). Это
«ИИ-сотрудники для компаний»: бот с профилем, владельцем и видимостью,
навыки и инструменты с выдачей на бота, одобрения действий, журнал,
расписания, общение ботов.

Берём сейчас, пока это дёшево:

- **Кому бот может писать.** У OpenBot инструмент `message_bot` есть только
  при явной выдаче «бот A может спрашивать бота B». У нас поле бота
  `reach`: `null` — всем (удобно одному владельцу), список — только этим.
  Проверка в той же транзакции, что и лимит цепочки; в инструкции бота
  попадают только доступные ему боты.
- **Журнал действий бота** (`bot_events`): кто сделал (`owner`, `agent` с
  id чата, `plugin` с id плагина), что и когда. Кто вызвал RPC, 1ma
  сообщает сам (`experimental_caller`), модель это подделать не может —
  та же идея, что подписанное «кто начал ход» у OpenBot. Отказы в письмах
  тоже пишутся. На странице бота — последние 20 записей.

Берём позже, когда понадобится, без переделки устройства:

- Владелец бота, видимость (личный, командный, опубликованный) и права —
  когда в 1ma появятся команды; сейчас один владелец сервера.
- Одобрения действий по видам (отправка, удаление, оплата) со «строже
  побеждает» — поверх встроенного инструмента вопросов и карточек
  суперагента.
- Расписания бота — на встроенном Automations, с правилами OpenBot:
  минимальный интервал, предел активных расписаний, выключение после 10
  сбоев подряд, пропущенное не догоняется.
- Шаблоны ботов (каталог готовых сотрудников) и бюджет бота в день — у
  OpenBot бюджета нет, у нас это будет преимуществом.

Не берём: отдельный компьютер (контейнер) на бота, язык правил CEL,
память «на человека» через их лицензируемый сервис, SCIM. Наша
приватная память бота с проверкой хеша аккуратнее, чем у них.

Поля и таблицы добавляются в базе плагина новыми шагами миграции
(`bb.storage.migrate`, только добавление), поэтому отложенное не требует
переделки данных.

## Варианты установки

Решение владельца 14.11.2026: не все клиенты 1ma работают с ботами, многие
обходятся чатами; на Linux владельца нет суперагента. Поэтому три плагина
независимы, и ни один не требует другого:

| Установлено                                            | Что видно и работает                                                                    |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| только штатный список или `1ma-sidebar` без `1ma-bots` | обычная панель 1ma, блока ботов нет                                                     |
| `1ma-bots` без `1ma-sidebar`                           | боты, их память и письма, страница «Боты», строка «Бот» в карточке чата; панель штатная |
| `1ma-bots` + `1ma-sidebar` (Linux владельца)           | всё выше и блок ботов в панели                                                          |
| то же + `1ma-superagent` (Mac владельца)               | плюс действия Главного бота в его чатах                                                 |

- `1ma-bots` ничего не знает о суперагенте: области работы — просто
  метки, их читает тот, кому они нужны. Без суперагента метка `dev`
  ничего не включает и ничего не ломает.
- Блок ботов в `1ma-sidebar` включается сам, когда `1ma-bots` установлен
  и отвечает, и выключается настройкой «Показывать ботов» на этом
  сервере. Пока ботов нет, от блока виден только заголовок «Bots +».
- Требование к коду и тестам: каждый плагин проверяется и в одиночку
  (`1ma-sidebar` без `1ma-bots` даёт ровно штатный список; `1ma-bots`
  без суперагента проходит все свои тесты).

## Решения владельца по этапу 0 (14.11.2026)

- Описание утверждено. Чат бота виден только под ботом.
- В первую версию добавляются перетаскивание чата на бота, отметка
  «готово» и сообщения между ботами.
- Вся панель в одной дизайн-системе. Блок ботов не задаёт своих шрифтов,
  размеров и цветов: только токены темы 1ma (`--font-sans`,
  `--foreground`, `--muted-foreground` и т. д.) и компоненты реестра
  (`@/components/ui/*`). Чаты бота рисуются той же строкой чата, что и
  штатный список (`ThreadRow` из копии), заголовки блока — тем же
  заголовком группы, что у проектов.
- Нужно продумать запуск и настройку новых ботов (раздел ниже).

## Создание и настройка бота

- В заголовке блока «Боты» есть `+ Новый бот`. Он открывает в основной
  области страницу бота из `1ma-bots`: имя, роль, лицо (с кнопкой
  «случайное»), области работы, инструкции, настройки новых чатов
  (провайдер, модель, проект). Обязательно только имя.
- После сохранения сразу открывается первый чат бота. Бот в нём
  расспрашивает владельца о работе и сам записывает инструкции и память
  своими инструментами, как в Grok Bot, где работу боту дают первым
  сообщением. Владелец видит и правит всё на той же странице.
- «Изменить» в меню бота открывает ту же страницу. Страница живёт в
  `1ma-bots`, поэтому ботов можно создавать и без `1ma-sidebar`.
- Инструмент `bot_update_identity` меняет имя, роль и инструкции только
  своего бота и проверяет ревизию; чужого бота агент изменить не может.

## Отметка «готово»

- «Готово» ничего не удаляет и не архивирует. Чат уходит из списка бота
  в свёрнутую строку «Готово: N» под ним. Новое сообщение, вопрос бота или
  письмо от другого бота сами возвращают его в список.
- По умолчанию «готово» только ручное. Автоотметку по простою можно
  включить в настройках плагина (часы простоя); первый чат бота и
  закреплённые чаты она не трогает никогда. Долгий чат вроде «Креативы»,
  который неделями ждёт задания, остаётся в списке.
- Архив — штатное действие 1ma в меню чата, отдельно от «готово»: архив
  не ставит «готово», «готово» не архивирует.
- Правило: чат, где ждут владельца (вопрос, ошибка, упавшая очередь),
  не бывает «готово». Сервер `1ma-bots` снимает отметку, как только
  чат требует внимания, и `bots.v1` не отдаёт оба состояния сразу.
- Home Dashboard (`plugins/1ma-home-dashboard`) «готово» `1ma-bots` не
  читает: полоса Done берётся из отметок Focus Board, «Needs you» — из
  живого состояния чата, и `laneFor` ставит «Needs you» первым. Поэтому
  один чат там не бывает одновременно сделанным и требующим внимания.
  Если панели понадобится «готово» ботов, она читает `bots.v1`, где по
  правилу выше противоречия нет.
- Тесты: простой без включённой автоотметки не ставит «готово»; новое
  сообщение, вопрос и письмо бота возвращают чат в список; архив и
  «готово» не меняют друг друга; чат с вопросом не отдаётся как
  «готово».

## Сообщения между ботами

- Инструмент `bot_message({ to, text, threadId? })`: письмо ставится в
  штатную очередь чата получателя (`bb.sdk.threads.send`). По умолчанию —
  в первый чат бота-получателя, `threadId` должен принадлежать ему.
  Отправитель — чат из контекста вызова инструмента (`ctx.threadId`,
  его задаёт 1ma), а не параметр. Письмо подписано ботом-отправителем.
- **Цепочку ведёт сервер.** Письмо, доставленное в чат, делает цепочку
  этого письма текущей цепочкой чата-получателя. Любое письмо из чата с
  текущей цепочкой продолжает её; из чата без цепочки — начинает новую.
  Ответа «вручную» к цепочке нет: модель не передаёт ни номер цепочки,
  ни счётчик. Текущую цепочку чата снимает только сообщение человека в
  этом чате: хук `message.dispatch` с `initiator: "user"` и
  `senderThreadId: null`. Письма ботов и `bb thread tell` из других чатов
  несут `senderThreadId` и цепочку не снимают. Прямой вызов HTTP API
  агентом с оболочкой вне модели угроз, как в ADR-0006 (пункт 6).
- **Общий лимит цепочки** — число всех писем в ней, а не глубина:
  A → B → C → A продолжает ту же цепочку, повторная отправка из того же
  чата тоже, и счётчик не сбрасывается. После лимита (по умолчанию 6)
  инструмент отказывает и предлагает спросить владельца. Второй лимит —
  писем от одного бота за час. Счётчик и проверка — одна транзакция в
  базе плагина, так что два одновременных письма не обходят лимит.
- **Один путь отправки.** В первой версии писать можно только
  инструментом. CLI `bb 1ma-bots list` только читает; команды отправки в
  CLI нет, потому что чат вызова у CLI приходит из окружения агента и
  может быть подменён, а значит, может обойти цепочку.
- Тесты: A → B → C → A и повторная отправка не сбрасывают счётчик; лимит
  срабатывает на заданном письме; параллельные письма не превышают
  лимит; `threadId` чужого бота отклоняется; сообщение владельца снимает
  цепочку.
