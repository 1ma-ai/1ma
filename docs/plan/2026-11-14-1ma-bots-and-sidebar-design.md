# Боты 1ma и блок ботов: описание первой версии (этап 0)

14.11.2026. Задание и решения владельца:
[2026-11-14-1ma-bots-and-sidebar.md](2026-11-14-1ma-bots-and-sidebar.md).
Шов с суперагентом: ADR-0006 (ветка `superagent`).

## Что изучено

- **Grok.** Custom Agents (март 2026): до четырёх агентов, у каждого имя,
  характер и инструкции до 4 000 символов, инструменты и файлы знаний.
  Grok Bot (бета с августа 2026): бот с именем, работой, аватаром и
  профилем; память своя у каждого бота; библиотека навыков общая для всех
  ботов; расписания (routines) у каждого бота свои; подключённые приложения
  общие; боты общаются сообщениями и через общие файлы, общей памяти нет.
  Отсюда устройство бота: личность и инструкции, своя память, общие навыки
  и инструменты, свои расписания.
- **Bots Sidebar 1.1.0** (`ff58530`, без лицензии; повторяем вид и
  устройство, код не берём). Заменяет весь список чатов через
  `experimental_threadList`. Бот: имя, роль, аватар, SOUL до 4 096 символов,
  память до 3 000 символов (дописывает сам агент инструментом с проверкой
  хеша), настройки нового чата, проекты. Чаты бота — дерево под ботом.
  Аватары сделаны по [bloub](https://github.com/jeremy-prt/bloub) (MIT).
- **Cursor Sidebar 0.3.5** (MIT). Тоже свой список целиком, на штатный не
  похож; для первой версии брать из него нечего.
- **1ma (bb 0.49.0, SDK 0.6.132).** Места «блок над проектами в штатном
  списке» нет. `app.slots.navPanel` даёт пункт навигации, а
  `experimental_threadList` заменяет список целиком. Штатный список чатов
  (`plugins/thread-list`) входит в список официально копируемых встроенных
  плагинов bb (`scripts/forkable-plugins.json`, `docs/forkable-plugins.md`),
  лицензия MIT. На Mac владельца выбран именно он, и Rail ставит New thread
  в шапку панели, сразу над списком.
- На Linux в базе Bots Sidebar ботов нет; боты владельца на Mac.

## Что берём готовым

| Нужно боту | Готовое в 1ma |
| --- | --- |
| Роль и инструкции в каждом чате бота | `bb.agents.configure` (`instructions` до 32 768 символов) |
| Навыки | общая библиотека навыков 1ma, как у Grok; бот называет нужные в инструкциях |
| Общая память о владельце и проектах | встроенный Memory (global, project) |
| Своя память бота | своя таблица; Memory не умеет область «бот» |
| Вопросы владельцу | встроенный инструмент вопросов |
| Расписания бота | встроенный Automations (после первой версии) |
| Новый чат с настройками бота | `experimental_NewThreadComposer` + создание чата сервером плагина |
| Состояние чатов (работает, ждёт, ошибка) | `useSidebarThreadRowStatus`, `experimental_ThreadStatusGlyph` |
| Меню чата (переименовать, архив и т. п.) | `experimental_ThreadActionsContextMenu` |
| Сама боковая панель | копия штатного `thread-list` |
| Аватары | своя отрисовка по bloub (MIT, с указанием авторства) |

## Бот

- Поля: id, имя, роль (подпись под именем), внешний вид (форма, цвет,
  выражение), инструкции, память (до 3 000 символов), возможности,
  настройки нового чата (провайдер, модель, рассуждение, права, проект,
  окружение), связанные проекты, порядок, скрыт ли.
- **Возможности** — список меток (`dev`, `marketing`, `accounting` и
  любые новые). `1ma-bots` их только хранит и отдаёт; что бот умеет в
  каждой области, включают другие плагины, прочитав
  `bots.v1.forThread`. Так бот готов к любой работе без изменения
  `1ma-bots`.
- **Чаты бота.** Принадлежность хранится в таблице `1ma-bots`, это
  источник истины. Чат, начатый из бота, создаёт сервер `1ma-bots`, и у
  него `originPluginId: "1ma-bots"`. У старого чата, привязанного к боту
  позже, этого признака нет, поэтому суперагент не включит в нём свои
  инструменты (ADR-0006: `configure` синхронный и RPC не зовёт). Чаты бота
  не скрываются и не заглушаются, иначе пропадут уведомления о вопросах.
- **Память бота.** В инструкциях каждого чата бота. Агент читает и меняет
  её инструментами `bot_memory_read` и `bot_memory_update` (дописать
  факт, забыть факт, заменить целиком по хешу последнего чтения). Факты
  обо всех проектах по-прежнему идут во встроенный Memory.

## Плагин `1ma-bots`

- Сервер: таблицы в базе плагина, RPC `bots.v1.list`, `bots.v1.forThread`
  (`{ threadId } → { botId, name, capabilities } | null`), чтение и правка
  бота, список его чатов, привязка и отвязка чата, начало чата.
  `bb.agents.configure` добавляет инструкции и память бота в его чаты;
  инструменты памяти, `bot_update_identity` и `bot_message`; один навык
  `1ma-bots` о том, как вести память и писать другим ботам.
- Интерфейс: пункт навигации «Боты» со списком ботов и редактором (имя,
  роль, внешний вид, инструкции, память, возможности, настройки нового
  чата, проекты). В шапке чата — «Бот: …», чтобы привязать чат к боту
  или отвязать. Работает с любой боковой панелью.
- Сообщения между ботами и их лимит — раздел «Сообщения между ботами».

## Плагин `1ma-sidebar`

- Копия штатного `thread-list` из bb `desktop-v0.49.0` (`7b26cae`),
  снятая процедурой bb (`scripts/lib/plugin-fork.mjs`), с `UPSTREAM.md`.
  Перенос апстрима и свои правки — разными коммитами. Свои правки —
  блок ботов сверху списка и вынос чатов бота из групп проектов: чат бота
  виден только под ботом, как в Bots Sidebar (решение владельца,
  14.11.2026).
- Блок ботов: заголовок «Боты» и `+` (новый бот). Строка бота: аватар
  с индикатором работы (круг вращается, когда работает первый чат бота;
  точки — другие работающие чаты; ожидание ответа и ошибка видны
  отдельно), имя, роль, число чатов и стрелка. Раскрытый бот показывает
  дерево своих чатов, старые свёрнуты в «Ещё N». Щелчок по боту
  открывает его первый чат; `+` при наведении — новый чат с настройками
  бота; меню бота: изменить, новый чат, скрыть.
- Данные блок берёт у своего сервера, а тот — у `1ma-bots` через
  `bb.sdk.plugins.callRpc`. Без `1ma-bots` блока нет, список работает как
  штатный.
- Выбирается в «Настройки → Внешний вид» как список чатов; навигация Rail
  остаётся штатной.

## Решения владельца по этапу 0 (14.11.2026)

- Описание утверждено. Чат бота виден только под ботом.
- В первую версию добавляются перетаскивание чата на бота, отметка
  «готово» и сообщения между ботами.
- Вся панель в одной дизайн-системе. Блок ботов не задаёт своих шрифтов,
  размеров и цветов: только токены темы 1ma (`--font-sans`,
  `--foreground`, `--muted-foreground` и т. д.) и компоненты реестра
  (`@/components/ui/*`). Чаты бота рисуются той же строкой чата, что и
  штатный список (`ThreadRow` из копии), заголовки блока — тем же
  заголовком группы, что у проектов.
- Нужно продумать запуск и настройку новых ботов (раздел ниже).

## Создание и настройка бота

- В заголовке блока «Боты» есть `+ Новый бот`. Он открывает в основной
  области страницу бота из `1ma-bots`: имя, роль, лицо (с кнопкой
  «случайное»), области работы, инструкции, настройки новых чатов
  (провайдер, модель, проект). Обязательно только имя.
- После сохранения сразу открывается первый чат бота. Бот в нём
  расспрашивает владельца о работе и сам записывает инструкции и память
  своими инструментами, как в Grok Bot, где работу боту дают первым
  сообщением. Владелец видит и правит всё на той же странице.
- «Изменить» в меню бота открывает ту же страницу. Страница живёт в
  `1ma-bots`, поэтому ботов можно создавать и без `1ma-sidebar`.
- Инструмент `bot_update_identity` меняет имя, роль и инструкции только
  своего бота и проверяет ревизию; чужого бота агент изменить не может.

## Отметка «готово»

- «Готово» ничего не удаляет и не архивирует. Чат уходит из списка бота
  в свёрнутую строку «Готово: N» под ним. Новое сообщение, вопрос бота или
  письмо от другого бота сами возвращают его в список.
- Автоматического «готово» по простою по умолчанию нет. Долгий чат вроде
  «Креативы», который неделями ждёт задания, остаётся в списке.
  Включается в настройках плагина (часы простоя); первый чат бота и
  закреплённые чаты не трогает никогда.
- Архив — штатное действие 1ma в меню чата, отдельно от «готово».

## Сообщения между ботами

- Инструмент `bot_message({ to, text, threadId? })`: письмо ставится в
  штатную очередь чата получателя (`bb.sdk.threads.send`). По умолчанию —
  в первый чат бота-получателя, `threadId` должен принадлежать ему. Письмо
  подписано отправителем и содержит способ ответить.
- Лимит в коде: у письма есть цепочка; ответ в той же цепочке
  увеличивает счётчик, и после заданного числа пересылок (по умолчанию 6)
  инструмент отказывает и предлагает спросить владельца. Ещё один лимит —
  число писем от одного бота другому за час.
- CLI `bb 1ma-bots message` и `bb 1ma-bots list` для агентов вне ботов.

## Не в первой версии

Разделы ботов, сменяющиеся выражения лиц, упоминания `@бот`, процессы
workflows внутри дерева, расписания бота. Добавляются после того, как
владелец посмотрит первую версию.

## Проверки

- Тесты на `@get-bb/plugin-sdk/testing` для сервера и интерфейса обоих
  плагинов; каждый тест видели красным.
- Копия `thread-list` проходит свои тесты bb без изменений.
- Вид и сквозная проверка (сервер 1ma, оба плагина, тестовые боты,
  снимки панели) — в GitHub Actions.

## Перенос (этап 3)

Codex на Mac читает базу Bots Sidebar только на чтение и выгружает ботов
в JSON: имя, роль, внешний вид, SOUL → инструкции, MEMORY → память,
проекты, привязки чатов. `bb 1ma-bots import` загружает файл, повторный
импорт ничего не дублирует. Bots Sidebar удаляется после приёмки.
