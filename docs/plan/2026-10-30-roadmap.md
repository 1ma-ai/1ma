# Дорожная карта 1ma на базе bb (черновик 30.10.2026)

Принцип: качество и масштабируемость важнее скорости. Каждый этап заканчивается
проверяемым результатом, тестами, документацией и тем, что владелец реально
пользуется сделанным. Решения фиксируем в `docs/adr/`.

## Как строятся такие проекты (методика)

1. Сначала решения, потом код: ADR на базу (bb), на структуру репозитория и
   инструменты, на формат плагинов. Решение можно поменять, но оно записано.
2. Инженерная система раньше функций: репозиторий, тулчейн, линт/формат, тесты,
   CI, релизы по тегам, маркетплейс, чеклист «готово». Это и есть защита от
   костылей: костыль не проходит CI и ревью.
3. Вертикальный срез: самый маленький сквозной результат, проверяющий всю
   цепочку (репо → плагин → маркетплейс → установка в bb → видно в приложении).
4. Дальше итерации по одному плагину за раз: спецификация (что именно меняем),
   реализация, тесты на SDK-харнессе, живой прогон, релиз тегом, запись в
   changelog. Владелец переключается на новую часть и живёт с ней.
5. Синхронизация с upstream по расписанию: bb выпускает релизы каждые
   несколько недель; у каждого форкнутого плагина есть зафиксированный коммит
   bb и скрипт, который показывает, что изменилось в оригинале.
6. Документация как код: README у каждого плагина, PLUGIN_OVERVIEW как в bb,
   AGENTS.md для агентов, работающих в репозитории.

## Слои 1ma (целевая картина)

```
[1ma Desktop]  брендированная оболочка (этап 5), пока — bb Desktop/npx bb-app
[1ma plugins]  тема, композер, сайдбар, home, затем: агенты-сотрудники (идеи
               Paperclip), learning loop (идеи Hermes), документы, коннекторы,
               анонимайзер-маршрутизация, Deep Research
[bb core]      server + host daemon + app + CLI + SDK — без изменений
[providers]    claude-code, codex, pi, acp (opencode, hermes, dsh, goose…)
[models]       подписки Claude/GPT, OpenRouter; позже on-prem и анонимайзер
```

## Этап 0. Фундамент (без функций)

Результат: пустой, но «взрослый» репозиторий и рабочее окружение.

- Репозиторий `1ma-ai/1ma` (монорепо плагинов): `plugins/<имя>/`,
  `.bb/plugins.json`, `marketplace/marketplace.json`, `docs/{adr,plan,research}`,
  `scripts/` (импорт форкабельного плагина из bb с записью upstream-коммита,
  проверка дрейфа), `AGENTS.md`, `CONTRIBUTING.md`, лицензия MIT.
- Тулчейн как у bb: Node 24, pnpm (corepack), TypeScript strict, oxlint/oxfmt,
  vitest + `@get-bb/plugin-sdk/testing`, `bb plugin build/dev`.
- CI (GitHub Actions): typecheck, test, build каждого плагина против
  зафиксированной версии `bb-app`; еженедельная проверка против `bb-app@nightly`.
- Релизы: теги `<plugin>/vX.Y.Z`; маркетплейс читает диапазоны; changelog.
- Окружение разработки: эта Linux-машина (плагины собираются esbuild, монорепо
  bb не собираем). Решить: обновить bb здесь до 0.48.x (форки композера и
  сайдбара требуют SDK ≥ 0.6.77).
- Перенос двух существующих локальных плагинов владельца (home-dashboard,
  server-switcher) в монорепо как первые жители.

Критерий готовности: `bb marketplace add` + `bb plugin install` ставят
плагин из репозитория 1ma на машине владельца; CI зелёный.

## Этап 1. Вертикальный срез: тема и шрифты

- Плагин `1ma-theme`: манифест `bb.themes`, светлая и тёмная палитра, шрифты
  владельца, код-тема. Один плагин, один маркетплейс, одна установка.
- Критерий: владелец выбирает тему 1ma в Settings → Appearance и живёт с ней.

## Этап 2. Композер 1ma

- Спецификация от владельца: что именно должно отличаться от композера bb.
- Форк `plugins/composer` по официальной процедуре bb → `1ma-composer`;
  `UPSTREAM.md` с коммитом; тесты на харнессе; живой прогон.
- Критерий: композер 1ma выбран в Settings → Appearance → Composer, ничего из
  функций bb (меншены, слэш-команды, вложения, голос, очередь) не потеряно.

## Этап 3. Сайдбар 1ma

- Спецификация; форки `thread-list` и `navigation` → `1ma-thread-list`,
  `1ma-navigation`; при необходимости `sidebar-footer`.
- Критерий: сайдбар 1ma активен, владелец работает только в нём.

## Этап 4. Home и ежедневный поток

- Объединить home-dashboard владельца и новые секции home; закрыть мелкие
  «чего не хватает в bb» пожелания владельца плагинами.
- Критерий (веха A, «заменить bb»): владелец использует bb-app + плагины 1ma
  для всей работы и не включает ничего из того, что 1ma заменил.

## Этап 5. Брендированный десктоп 1ma

- Тонкий форк `apps/desktop` + `packages/bb-app`: имя, логотип, иконка,
  предустановленные плагины 1ma, предзаданный маркетплейс, тема по умолчанию,
  автообновление с нашего канала. Сборка и подпись на Mac владельца.
- Критерий: установщик 1ma для macOS (затем Linux/Windows), «чистая» установка
  у нового пользователя даёт готовый 1ma.

## Этап 6+. Company OS (каждый пункт — отдельный ADR и плагин)

- Движки: конфигурации provider-acp для OpenCode/Hermes/dsh/goose; лучшие
  практики выбора движка под задачу.
- Агенты-сотрудники: роли, расписания (bb automations), бюджеты, approvals,
  routines (модель Paperclip; интеграция сервисом или перенос модели в плагины).
- Learning loop: опыт и правки → скиллы (модель Hermes) поверх bb memory/skills.
- Документы: образ песочницы с LibreOffice и сборщиками docx/xlsx/pptx из
  legacy; environment-provider плагин.
- Коннекторы РБ/РФ: Битрикс24 (официальный MCP), 1С (экосистема MCP),
  Directum (rxmcp); управление MCP-конфигами провайдеров из 1ma.
- Анонимайзер как маршрутизация провайдеров (env/base URL) и on-prem модели.
- Deep Research как workflow/скилл из legacy-движка.
- Совместимость плагинов Claude/GPT (отдельное обсуждение, ADR-0003).
- Веб-версия и многопользовательский режим (далёкий этап).

## Открытые вопросы к владельцу
