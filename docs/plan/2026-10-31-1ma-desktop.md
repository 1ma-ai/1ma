# 1ma Desktop: что это, кому нужно и как сделаем

Предложение от 31.10.2026, решения владельца внизу. Способ сборки закреплён в
ADR-0004.

## Коротко

1ma Desktop — собственное приложение 1ma для Mac, Windows и Linux. Внутри тот
же движок bb, но с именем 1ma, иконкой-человечком, плагинами и темой 1ma,
своим каналом обновлений и своими настройками по умолчанию. Человек ставит его
один раз, как Telegram или Zoom, и дальше оно обновляется само.

Сейчас владелец работает в bb Desktop с плагинами 1ma. Для него это рабочий
вариант, а для клиентов нет:

- в Dock, меню, установщике и окне «О программе» написано bb;
- первый запуск предлагает аккаунт getbb.app через GitHub и облачные функции
  bb;
- плагины 1ma нужно ставить вручную из нашего маркетплейса;
- приложение обновляется с серверов bb и по умолчанию отправляет bb
  анонимную статистику использования.

## Как клиенты будут получать 1ma

| Способ                                         | Кому                              | Что нужно сделать до запуска                                                                                                  |
| ---------------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 1ma Desktop на каждом компьютере               | первые клиенты, малый бизнес, Mac | этот документ, этап 5a                                                                                                        |
| 1ma в браузере с нашего сервера, без установки | клиенты на Windows, команды       | вход по логину и паролю и отдельный экземпляр на человека: у bb нет логинов, его API открыт любому, кто достучался до сервера |
| Сервер 1ma в контуре компании                  | крупные клиенты                   | то же, что для браузера, плюс поставка на их железо                                                                           |

Способы не исключают друг друга: десктоп умеет подключаться к удалённому
серверу, так что позже один и тот же 1ma Desktop работает и с локальным
сервером, и с сервером компании.

каждым выпуском bb.

## Как успевать за bb

- Репозиторий `1ma-ai/1ma-desktop`: публичный форк `get-bb/bb`, поверх него
  короткая серия наших коммитов с описанием в `PATCHES.md`.
- Каждый день робот сверяет выпуски bb (для плагинов он уже работает), кладёт
  нашу серию правок поверх нового выпуска, собирает приложения, запускает
  смоук-тесты bb и выпускает 1ma Desktop той же версии. Конфликт правок
  превращается в задачу, которую закрываем в тот же день.
- Сборки идут на машинах GitHub. Для публичных репозиториев это бесплатно,
  включая Mac.
- Дальше предлагаем авторам bb поддержку white-label-сборки: имя, иконки,
  адрес обновлений, папка данных и встроенные плагины задаются одним файлом.
  Тогда наша правка сожмётся до этого файла. Это совпадает с принципом bb
  «подстраиваться под инфраструктуру пользователя, а не заставлять форкать».

## Платформы

- **Mac на Apple Silicon** — первым: у bb это самая зрелая платформа, и на
  нём работает владелец.
- **Windows** — у bb нативная Windows пока в статусе alpha и требует Git for
  Windows. В Беларуси и России у малого бизнеса преобладает Windows, поэтому
  до продаж нужна проверка на реальных машинах. Запасной путь для таких
  клиентов — 1ma в браузере с нашего сервера.
- **Linux** — AppImage, у bb тоже alpha.

## Подпись приложения

Владелец живёт и работает в Польше, поэтому ограничения для Беларуси и России
на подпись не влияют.

- **Mac без подписи.** При первом запуске macOS блокирует приложение. Нужно
  открыть Системные настройки, Конфиденциальность и безопасность, нажать
  «Открыть всё равно» и ввести пароль; дальше приложение запускается как
  обычно. Автообновление на Mac без подписи не работает: macOS ставит
  обновление, только если его подпись совпадает с подписью установленного
  приложения. Поэтому неподписанная сборка лишь сообщает о новой версии, а
  ставится она скачиванием, и каждая новая скачанная версия снова требует
  «Открыть всё равно».
  Такая сборка всё равно подписывается локальной подписью без аккаунта Apple
  (ad-hoc): совсем без подписи Mac на Apple Silicon называет скачанное
  приложение повреждённым и кнопку «Открыть всё равно» не показывает.
  Разрешения вроде микрофона macOS может спрашивать заново после каждой
  новой версии.
- **Mac с подписью.** Apple Developer Program, 99 долларов в год, из Польши
  доступна частному лицу; в окне установки будет имя владельца, позже можно
  перейти на компанию. С подписью и нотаризацией первый запуск задаёт один
  обычный вопрос, а обновления ставятся сами.
- **Windows без подписи.** SmartScreen при запуске скачанного установщика
  показывает «Windows защитила ваш компьютер»; дальше «Подробнее» и
  «Выполнить в любом случае». Это происходит при запуске скачанного файла:
  установленное приложение запускается без предупреждений, а обновления,
  которые приложение скачивает само, SmartScreen не проверяет. На части
  компьютеров с Windows 11 включён Smart App Control, он неподписанные
  приложения блокирует без возможности обойти.
- **Windows с подписью.** Частному лицу из Польши доступен обычный сертификат
  подписи, например у польского удостоверяющего центра Certum, около 200–250
  евро в год. Компании из ЕС доступна Azure Artifact Signing за 9,99 доллара
  в месяц. Предупреждение SmartScreen исчезает не сразу, а по мере того как
  у подписи набирается репутация.
- Пока приложение ставит сам владелец, подпись не обязательна. До раздачи
  клиентам нужна подпись для Mac, а для Windows она нужна точно.

## Что ещё нужно клиентам кроме приложения

- **Модели из коробки.** Онбординг bb требует установленного и залогиненного
  агента (Claude Code, Codex, Pi или ACP-агент). Клиент малого бизнеса этого
  делать не будет. 1ma Desktop должен приходить с агентом, уже настроенным на
  ключ моделей 1ma: сейчас OpenRouter, потом через анонимайзер и биллинг.
- **Свой первый запуск** на понятном языке, без шагов для разработчиков
  вроде git и worktree.
- **Поддержка**: сбор логов и удалённая помощь.

## План

Этап 5a. 1ma Desktop для владельца, Mac:

1. Создать `1ma-ai/1ma-desktop` как публичный форк bb.
2. Серия правок из таблицы выше.
3. Сборка на машинах GitHub: сначала Mac, без подписи.
4. Смоук-тесты bb для упакованного приложения в той же сборке.
5. Владелец ставит 1ma Desktop и переносит данные из bb штатными командами
   bb: `bb server export`, затем `bb server import` в папку 1ma. bb Desktop
   остаётся запасным вариантом.
6. Ежедневное следование за выпусками bb.

Этап 5b. Готовность к клиентам: проверка Windows, решение по подписи, модели
из коробки, понятный первый запуск.

Оценка этапа 5a: один-два рабочих дня, в основном на сборку в CI. Windows и
Linux добавляют ещё около дня, автоматическое следование за bb ещё около дня.
Оценка грубая: сборка всего движка bb в CI ещё не проверена.

## Риски

- bb быстро меняется, и правки могут конфликтовать с новыми выпусками. Ответ:
  маленькая серия правок, ежедневная автоматическая сборка, предложение
  white-label-конфига авторам bb.
- bb может сменить лицензию в будущих версиях. Код, выпущенный под MIT,
  остаётся под MIT, и форк сохраняет к нему доступ.
- Нативная Windows у bb в статусе alpha.
- Подпись для Беларуси и России может оказаться недоступной без юрлица в
  другой стране.

## Решения владельца (07.11.2026)

1. Два отдельных 1ma, как сейчас два bb: на Mac и на Linux-машине, у каждого
   свои данные. Телефон потом подключается к 1ma на Mac.
2. Переезд с bb на 1ma — на каждой машине отдельно. На Mac его делает
   Codex владельца по инструкции (computer use), Linux-сервер переключает он
   же по SSH: изнутри треда сервер перезапускать нельзя.
3. bb пока не удаляется; держать запущенным одно из двух (один порт 38886) на
   переходный период устраивает. Отдельный порт для 1ma не нужен.
4. Подпись Apple — позже.
5. Встроенные плагины подписаны автором 1ma: их всё равно будут менять
   (как минимум перевод), поэтому переименование сразу на уровне всей
   системы. Лицензионное уведомление bb (MIT) остаётся.
6. Вопрос о сервере на Linux, слушающем 0.0.0.0, снят: порт 38886 по
   публичному адресу машины закрыт (проверено с самой машины по IPv4 и
   IPv6, открыт только SSH), подключения к bb приходят через проброс порта
   хоста. Тот же запуск сохраняется для 1ma.

## Следующие шаги этапа 5a

1. **Полный ребрендинг строк** (идёт, ADR-0005; дальше этап 2 —
   облачные службы bb и ссылки на getbb.app, этап 3 — команда терминала,
   навыки и ветки). В выпуске bb около 875 разных видимых строк
   со словом bb: веб-часть 127, оболочка 65, сервер 101, командная строка 158,
   встроенные плагины 422, плюс пять навыков с bb в названии и ссылки на
   getbb.app. Их меняет не ручная правка, а преобразование при сборке по
   списку правил, и проверка, которая падает, если в интерфейсе появилась
   новая строка с bb. Остаются только текст лицензии MIT и внутренние имена в
   коде, которых пользователь не видит.
2. **Плагины и тема 1ma внутри приложения**, чтобы после установки ничего не
   нужно было ставить из маркетплейса.
3. **Канал выпусков** (11.11.2026 сделана основа): сборка нумеруется как
   ночные сборки bb — следующий патч выпуска bb с пометкой запуска,
   `0.49.1-1ma.<запуск>.<попытка>` (`desktop/scripts/version.mjs`); она новее
   выпуска bb, на котором собрана, и всех прежних сборок 1ma, старше
   следующего выпуска bb. Движок плагинов bb сравнивает через
   `semver.coerce`, поэтому для плагинов сборка выглядит на патч новее bb
   (от несовместимого API защищает проверка версии SDK). Выпуск
   `desktop/v<версия>`, после публикации `desktop-release.yml` переписывает
   только вперёд `desktop-version.json` (его смотрит приложение) и
   `server-version.json` (его смотрит сервер) в выпуске `desktop-latest`.
   Осталось: ежедневная пересборка на каждый новый выпуск bb; после подписи
   Apple вернуть на Mac автоустановку и выкладывать в `desktop-latest` ещё
   `latest-mac.yml` и zip; Windows до подписи — только проверка версии без
   автоустановки (сейчас правка 0004 оставляет её там включённой); готовить
   дерево один раз на push и передавать артефактом, а не 18 раз.
4. **Перенос данных владельца** (готово): Mac переехал 08.11.2026, Linux —
   10.11.2026; bb удалён с Linux 11.11.2026. Рабочих папок тредов и
   проектов внутри `~/.bb` не было ни на одной машине. На Mac bb отложен
   11.11.2026 (`docs/runbooks/mac-remove-bb.md`): службы и профили владельца
   перенесены из `~/.bb`. Осталось: отложенная проверка через день после
   перезагрузки и шаг 8 (удаление отложенного) только по слову владельца.
5. **Сервер обновляется сам из выпусков 1ma** (правка 0009, 11.11.2026).
   Встроенное обновление bb ставило `bb-app@<версия>` из npm, то есть bb
   вместо 1ma. Публиковать в npm не стали: имя `bb-app` там принадлежит bb, а
   переименование пакета задевает пути `node_modules/bb-app` в коде bb. Теперь
   сервер берёт версию из `server-version.json` в `desktop-latest`, а пакет
   `1ma-server-<версия>.tgz` — из выпуска `desktop/v<версия>`, сверив с его
   `SHA256SUMS`, и ставит его `npm install` по файлу. Проверку раз в час,
   установку, когда 15 минут не работал ни один тред, и перезапуск делает
   механизм bb (прежняя версия остаётся на диске) (эксперимент `updateWhenIdle` и
   `bb updates app auto on`). `ONEMA_UPDATE_COMMAND_PREFIX` пускает установку
   через обёртку: на Linux владельца это очередь heavy
   (`/home/dev/.local/bin/1ma-update-heavy`). На Linux включено 11.11.2026 по
   `docs/runbooks/linux-enable-self-update.md` (запуск из
   `/home/dev/.local/opt/1ma-server`, без `--no-in-app-updates`), первое
   обновление прошло само. Приложение на Mac до подписи ставит Codex по
   `docs/runbooks/mac-update-1ma.md`.
   Повтор упавшей установки через шесть часов (прежняя правка 0011) убран
   13.11.2026: очередь heavy — особенность одной машины; если установка
   упадёт, её ставит следующий выпуск или `bb updates app apply`.
   Независимое ревью (11.11.2026) нашло и закрыто: выпуск падал на пустом
   `desktop-latest`, два выпуска сразу могли откатить фиды, опубликованные
   файлы перезаписывались. Осталось: подпись `SHA256SUMS` ключом ed25519
   (секрет в GitHub кладёт владелец, открытый ключ — в правку 0009; сейчас
   сумма лежит в том же выпуске и ловит только порчу); подсказки `npx bb-app`
   в сообщениях bb ставят bb;
   тесты на 404 и прерывание скачивания; `commandPrefix: []` в тестах
   контроллера.
6. После переезда строка `source` у плагина из папки данных bb показывает
   старый путь `path:~/.bb/...`, хотя сам плагин загружается из `~/.1ma`
   (bb переписывает при импорте только пути, по которым загружает).
7. **Временные решения и что их заменит** (правило «без костылей», 13.11.2026):
   - Скрипт автоматизации, который ждёт свободных тредов перед
     `bb updates apply`, остался только на Mac до установки плагина
     `1ma-auto-updates` 0.2.0 (на Linux заменён 13.11.2026).
   - Подсказки `npx bb-app` в сообщениях bb ставят bb, а не 1ma. Заменят
     этапы 2–3 ребрендинга (своя команда и подсказки 1ma).
   - Приложение на Mac обновляется вручную. Заменит подпись Apple и
     автообновление (владелец, позже).
   - Выпуск на коммите, который меняет файлы `.github/workflows`, создаётся
     вручную (GITHUB_TOKEN получает 403). Заменит выпуск по тегу, который
     ставит сопровождающий, или токен GitHub App; случай редкий, только при
     изменении самих workflow.
   - `SHA256SUMS` лежит в том же выпуске и ловит только порчу файла. Заменит
     подпись обновлений ключом, который хранится не в том же GitHub, вместе с
     подписью Apple перед выдачей клиентам; ключ в секретах того же
     репозитория почти ничего бы не защищал.
   - Три теста bb про git в CI признаны известными сбоями из-за Git 2.56 на
     машинах GitHub. Заменит исправление тестов в серии или закреплённая
     версия git.
     Решено и в список не входит: на Linux служба 1ma убирает из своего
     окружения переменную контейнера (`env -u`): это настройка самой службы, а
     пересоздавать ради неё весь контейнер — лишний риск. Правки в bb не
     предлагаем (решение владельца 13.11.2026): серия держит их сама.
8. **Правки bb по ревью Codex: решения владельца 13.11.2026** (правило: правка
   bb чинит ошибку или явно улучшает bb для 1ma, владелец выбирает из
   вариантов с обоснованием):
   - Правка 0010 исправлена: исчезнувший файл Codex (обновление удалило
     версию, из которой запущен процесс) считается обновлением, тред
     продолжается на новом Codex. Тест на этот случай падал на прежней правке.
   - Новая правка 0013: встроенные плагины (провайдеры среди них) грузятся
     раньше установленных, медленный установленный плагин их больше не держит.
     Причину долгой сборки `msg8-release-hooks` на Mac всё равно ищем.
   - «Send now» во время установки CLI: владелец оставил как есть. В bb есть
     штатная блокировка отправки, которую он ставит на время своего
     обновления и которая действует даже на «Send now»; распространить её на
     установку CLI можно правкой bb, если это понадобится.
   - Правка 0012: подписки отключённой машины или источника, который не
     ответил, в «All locations» без пометки — владелец оставил как есть.
     Второй запрос расхода той же подписки нужен: аккаунт, под которым Codex
     вошёл на машине, известен только после чтения расхода
     (`provider-codex/src/usage-source.ts`).
   - Журнал Account Pooler правка не нужна: строка «codex transport failed:
     UND_ERR_CONNECT_TIMEOUT» уже говорит, что не установилось TCP-соединение
     с chatgpt.com за 10 с (обе семьи адресов пробуются автоматически).
     Причина — связь Mac, проверяет Codex.
