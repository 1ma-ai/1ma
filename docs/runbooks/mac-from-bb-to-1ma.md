# Переезд Mac с bb на 1ma (инструкция для Codex)

Инструкцию выполняет Codex владельца на его Mac (computer use и терминал).
Владелец копирует её целиком. Значения подставлены для выпуска
desktop/v0.49.0-1ma.42358180199.

```text
Задача: перевести этот Mac с приложения bb на приложение 1ma. 1ma — это bb под другим брендом (та же программа, данные в ~/.1ma вместо ~/.bb). Нужно установить тестовую сборку 1ma и перенести в неё всё из bb (проекты, треды с историей, настройки, плагины, тему) штатными командами bb. bb не удалять: он остаётся запасным вариантом.

Правила, которые нельзя нарушать:
- Ничего не удалять. Папку ~/.bb только читать, ничего в ней не менять, не переименовывать и не чистить.
- Никогда не держать bb и 1ma запущенными одновременно: оба используют порт 38886.
- Файл экспорта содержит секреты и не зашифрован: никуда его не отправлять и не загружать, держать в ~/1ma-migration.
- Не отключать Gatekeeper и SIP, не снимать атрибут карантина (xattr) — только кнопка «Open Anyway» в настройках.
- Если что-то не совпадает с описанием (версии, пути, суммы, ошибки команд) — остановиться и прислать владельцу вывод, не импровизировать с данными.
- Команды шагов 2–11 выполнять вне песочницы Codex (с подтверждением владельца или в режиме полного доступа): в песочнице нет сети и записи вне рабочей папки, а pgrep, lsof и проверки скрипта могут не увидеть работающий bb.

Это нормально и не повод останавливаться:
- строки вида «ERROR:electron/shell/common/mac/codesign_util.cc:79] task_name_for_pid: (os/kern) failure (5)» перед выводом команд bb и 1ma: это журнал Electron, который не смог проверить подпись запустившего его процесса; команда при этом работает, смотреть на её код выхода и вывод;
- папка ~/.1ma или приложение /Applications/1ma.app от прежней пробной 1ma: шаг 3 заменяет приложение, а --move-aside откладывает папку как ~/.1ma.before-migration-<время>;
- белое окно bb: экспорт идёт через командную строку, а интерфейс bb, пока он запущен, открывается в браузере по адресу http://127.0.0.1:38886. Ничего не нажимать в окнах bb во время шагов 4–5.

Шаг 0. Подготовка, bb ещё работает.
- В bb дождаться, пока ни один тред не работает (нет треда в состоянии работы агента), или остановить их.
- В меню Server приложения bb должен быть выбран «This Mac» (локальный сервер). Если выбран другой сервер — переключить на This Mac.
- Записать URL Linux-сервера из того же меню Server (сохранённый пользовательский адрес) или из поля customServerUrls в ~/Library/Application Support/bb/server-target.json: он понадобится в шаге 11.

Шаг 1. Версия bb. В терминале: ~/.bb/bin/bb --version
Должно быть 0.49.0 или меньше. Если больше — остановиться и сообщить владельцу (нужна новая сборка 1ma). Если файла ~/.bb/bin/bb нет — сообщить.

Шаг 2. Скачать 1ma и проверить сумму.
mkdir -p ~/1ma-migration && cd ~/1ma-migration
curl -fL -o 1ma-0.49.0-arm64-42358180199.dmg "https://github.com/1ma-ai/1ma/releases/download/desktop/v0.49.0-1ma.42358180199/1ma-0.49.0-arm64-42358180199.dmg"
shasum -a 256 1ma-0.49.0-arm64-42358180199.dmg
Сумма должна быть ровно d1f5889fa9f2a4c0fd3d13c1debfcbe1a1488428c42d604138dadd52466d59e1. Иначе — остановиться.

Шаг 3. Установить: открыть 1ma-0.49.0-arm64-42358180199.dmg, перетащить 1ma в Applications, извлечь образ. Пока не запускать.

Шаг 4. Экспорт из bb (bb запущен, выбран This Mac). Сначала убедиться, что порт 38886 слушает сервер этого bb:
cat ~/.bb/bb-app-runtime.json
lsof -nP -iTCP:38886 -sTCP:LISTEN
ps -o pid,ppid,command -p <pid из файла>,<PID из lsof>
pid в файле — запускающий процесс bb-app-bridge.mjs, а порт слушает его дочерний сервер: у PID из lsof ppid равен pid из файла (или это тот же процесс). version в файле — версия из шага 1, оба процесса — из /Applications/bb.app. Иначе остановиться и прислать вывод. Потом:
~/.bb/bin/bb settings experiment serverMove true
~/.bb/bin/bb server export --out ~/1ma-migration/bb-server.tar
Должно закончиться строкой «Exported the bb server to …». Сохранить вывод и сразу переходить к шагу 5: всё, что сделано в bb после экспорта, в 1ma не попадёт.

Шаг 5. Полностью выйти из bb (Cmd+Q в bb). Проверить, что он не работает:
pgrep -lf "/bb.app/" ; lsof -nP -iTCP:38886 -sTCP:LISTEN
Обе команды ничего не выводят. Иначе подождать минуту и проверить снова. Если процессы bb остались (сервер запущен не этим окном и пережил его выход), остановить их так же, как bb останавливает сервер, который запустил не он: сначала убедиться командой ps -o pid,command -p <pid из ~/.bb/bb-app-runtime.json>, что это всё ещё bb-app-bridge.mjs из /Applications/bb.app, и выполнить kill -TERM <этот pid>: он сам остановит сервер и демон машины. Подождать до минуты и проверить снова. Если запускающего процесса уже нет, а порт 38886 всё ещё слушает процесс из /Applications/bb.app — kill -TERM <PID из lsof>. kill -9 не использовать. Если bb всё равно не выходит — сообщить. Скрипт переноса тоже откажется работать, пока bb запущен.

Шаг 6. Первый запуск 1ma, чтобы macOS его разрешила. Открыть /Applications/1ma.app. macOS скажет, что не может проверить приложение: System Settings → Privacy & Security → внизу «Open Anyway» для 1ma → пароль. Когда откроется окно 1ma (приветствие или настройка), ничего не настраивать: сразу выйти из 1ma (Cmd+Q) и проверить, что он завершился:
pgrep -lf "/1ma.app/" ; lsof -nP -iTCP:38886 -sTCP:LISTEN
Обе команды ничего не выводят. Этот запуск создал пустую папку ~/.1ma — следующий шаг аккуратно отложит её в сторону.

Шаг 7. Скрипт переноса из репозитория 1ma и его сумма:
curl -fL -o ~/1ma-migration/migrate-from-bb.mjs "https://raw.githubusercontent.com/1ma-ai/1ma/f4b45aa7b9bae32466e0a341371f6ef51f7c9518/desktop/scripts/migrate-from-bb.mjs"
shasum -a 256 ~/1ma-migration/migrate-from-bb.mjs
Сумма должна быть ровно 1637bca97e35a1c5b76d67c0663c8fb507b16bc1ff01abd97e206d18e0b467fe.

Шаг 8. Найти командную строку внутри 1ma:
find /Applications/1ma.app -path '*app.asar.unpacked/node_modules/bb-app/dist/bb.js'
Должна быть ровно одна строка, обычно /Applications/1ma.app/Contents/Resources/app.asar.unpacked/node_modules/bb-app/dist/bb.js. Дальше это CLI.

Шаг 9. Пробный прогон, ничего не меняет:
ELECTRON_RUN_AS_NODE=1 /Applications/1ma.app/Contents/MacOS/1ma ~/1ma-migration/migrate-from-bb.mjs import --archive ~/1ma-migration/bb-server.tar --cli "<CLI>" --move-aside --dry-run
Проверить вывод: «bb data: /Users/<имя>/.bb», «1ma data: /Users/<имя>/.1ma», строка «move the current … aside», список того, что будет скопировано. Сохранить вывод.

Если пробный прогон называет процессы не bb, которые работают в своей папке внутри ~/.bb (например, локальная почта), остановить их штатно: перенос эти папки не копирует и не трогает. Прислать владельцу, что остановлено и как это было запущено; если плагин работает с такой папкой, перед шагом 11 создать ссылку ln -s ~/.bb/<папка> ~/.1ma/<папка>.

Шаг 10. Перенос: та же команда без --dry-run. Должно закончиться строками «imported … files exported by bb …» и «next: start 1ma». Если скрипт отказывает (запущенные процессы, экспорт старше работы в bb, ошибка импорта) — остановиться и прислать вывод целиком; при ошибке он сам возвращает отложенную папку на место. Ничего не удалять.

Шаг 11. Запустить 1ma (bb не запускать). Если он открылся не на This Mac, переключить в меню Server на This Mac. Проверить:
- в боковой панели те же проекты и треды, что были в bb; открыть 2–3 треда — история на месте;
- Settings → Machines: одна машина — этот Mac, с ролью server и статусом connected; второй выключенной копии Mac нет;
- Settings → Plugins: плагины 1ma на месте (1ma Theme, 1ma Brand, 1ma Home Dashboard, 1ma Server Switcher и что было ещё), тема 1ma; ни одного плагина с ошибкой (плагин, установленный из рабочей папки треда, надо поставить заново из его папки). Облачные плагины bb (bb account, bb cloud AI, bb connect) в 1ma выключены, если их не включали в bb вручную: это ожидаемо, их включает владелец; в отчёте перечислить выключенные плагины;
- Claude Code и Codex видят вход (в настройках провайдеров или обновлений указан аккаунт или план);
- в любом проекте создать новый тред с Claude Code и написать: «Ответь одним словом: работает» — ответ приходит; потом этот тред можно архивировать;
- в терминале: ~/.1ma/bin/bb machine list и ~/.1ma/bin/bb thread list — вывести и сохранить;
- добавить Linux-сервер: меню Server → пользовательский адрес → URL из шага 0; убедиться, что он открывается (там пока bb), и вернуться на This Mac.

Шаг 12. Отчёт владельцу: версия bb из шага 1, суммы из шагов 2 и 7, вывод шагов 4, 9, 10, вывод команд шага 11, скриншоты боковой панели и Settings → Machines, все предупреждения и ошибки. Файл ~/1ma-migration/bb-server.tar не удалять, пока владелец не подтвердит, что всё работает.

Папку ~/.bb не удалять и после переезда: 1ma продолжает работать в её рабочих папках (рабочие деревья git, проекты, которые bb клонировал).

Если что-то пошло не так, откат: выйти из 1ma и открыть bb — его база такая, какой была при экспорте. Папку ~/.1ma не удалять; чтобы начать заново, переименовать её (например в ~/.1ma.failed-<дата>) и повторить с шага 9.
```
