## 4. Выводы для архитектуры (гипотеза до ответов владельца)

1. **Ядро — свой «1ma Server»** (TypeScript, Postgres): tenant/users/RBAC/SSO/audit/billing, каталог агентов и скиллов, коннекторы (MCP-реестр), очередь задач и расписания, память (Hindsight-подобная на Postgres) и learning loop. Модель данных и плагинная система — по образцу bb (threads/environments/hosts/plugins), оргмодель агентов — по образцу Paperclip (роли, бюджеты, heartbeats, approvals, routines).
2. **Движки агентов — сменные через ACP**: OpenCode (дефолт, MIT), dsh/goose как альтернативы, Claude Code/Codex для клиентов с подписками; каждый запуск — в песочнице (microVM/контейнер) с LibreOffice-стеком для документов. Это снимает вендор-лок и даёт «лопату» интеграторам.
3. **Координатор** — наш собственный агент над движками: маршрутизация задач по агентам/инструментам/данным, HITL-политики, память; его профиль персонален для сотрудника.
4. **Суверенный контур**: anonymizer в пути к любой внешней модели; on-prem модели через vLLM/OpenAI-совместимый endpoint.
5. **Из legacy переносим**: anonymizer (как есть), DR-движок (чистый LangGraph-модуль → в координатора/скилл), docx/xlsx/pptx builders + bench (в образ песочницы), BFF-паттерн админки, DESIGN.md. LibreChat-форк живёт как «этап 1» до переноса чата.
6. **Каналы**: web + Telegram в MVP (Hermes/OpenClaw-паттерн гейтвея), далее Bitrix24/почта.
