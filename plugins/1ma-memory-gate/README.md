# 1ma Memory Gate

Плагин 1ma: новый ход чата ждёт в очереди, пока на его машине не хватает
памяти. Если память свободна — чат стартует, если нет — ждёт. Встроенный
лимит числа тредов (`concurrency-limit`) остаётся потолком; этот плагин
добавляет условие по памяти в ту же точку допуска (хук `message.dispatch`).

## Правило

Для хода `start-turn` треда, который ещё не работает, на машине H:

1. Плагин выключен, у треда нет машины или это `join-turn` — ход идёт.
2. Машина не отдаёт показания памяти (не Linux) — ход идёт.
3. Показаний нет или они старше 15 секунд — ход ждёт 2 секунды, сборщик
   читает память сразу. Если ходы на H спрашивают 30 секунд подряд, а
   показаний всё нет, ход идёт без проверки и в журнал пишется
   предупреждение: сломанное чтение памяти не держит чаты вечно, лимит числа
   тредов продолжает стеречь машину.
4. На H работает меньше чатов, чем **Always allow this many chats**
   (по умолчанию 1), — ход идёт. Считаются треды, которые сервер называет
   работающими (`sdk.threads.listRunning()`).
5. `free = min(лимит cgroup − рабочий набор cgroup, MemAvailable машины)` по
   тем значениям, что есть. Каждый другой работающий на H тред, пропущенный
   плагином за последние 45 секунд, держит ещё одну долю **Memory per chat**:
   его память ещё не видна в показаниях. Ход идёт, когда
   `free ≥ доля × (такие треды + 1)` и давление памяти (`full avg10`) ниже
   **Memory pressure limit**; иначе ждёт 15 секунд с причиной вроде
   `Waiting for memory on <машина>: 0.4 GB free, 0.6 GB needed`.
6. Любая неожиданная ошибка пишется в журнал, и ход идёт: лимит числа тредов
   всё равно стережёт.

Учёт пропущенных тредов и останавливает всплеск: три чата из очереди,
перепроверенные одним проходом, не видят одну и ту же свободную память.
Доля держится только за тредом, который действительно стартовал: core
записывает статус пропущенного хода до того, как спросит о следующем, поэтому
тред, который пропустил этот плагин, но придержал другой (например, лимит
числа тредов), в списке работающих не появляется и памяти не занимает.

После завершения, сбоя, архивации или удаления треда и после изменения
настроек плагин просит core перепроверить придержанные сообщения
(`experimental_hooks.recheck`).

## Как читается память

Хост-часть (`host.ts`) на каждой машине читает файлы ядра Linux, каждый не
больше 64 КБ:

- cgroup v2 корня контейнера процесса: `/sys/fs/cgroup/memory.max`,
  `memory.high`, `memory.current`, `memory.stat` (`inactive_file`),
  `memory.pressure`;
- машина: `/proc/meminfo` (`MemAvailable`), `/proc/pressure/memory`.

Лимит — меньшее из `memory.high` и `memory.max` (литерал `max` значит «нет
лимита»), рабочий набор — `memory.current − inactive_file`, как в Kubernetes.
Давление берётся из файла cgroup, а без него — из файла машины. Отсутствующий
или испорченный файл обнуляет только своё поле; строка без завершающего
перевода строки считается обрезанной и не читается. Без `memory.stat`
рабочим набором считается весь `memory.current`.

Сервер (`server.ts`) опрашивает каждую подключённую машину каждые 5 секунд
(`bb.hosts.experimental_client`) и сразу после её подключения. Сбой опроса
пишется в журнал, повторы реже (до раза в минуту), старое показание просто
стареет.

## Настройки

Меняются в настройках плагина в приложении или `bb plugin config`:

- **Wait for free memory** (`enabled`) — по умолчанию включено.
- **Memory per chat (MB)** (`reserveMb`) — 600, от 64 до 65536.
- **Memory pressure limit (%)** (`pressurePercent`) — 10, от 1 до 100.
- **Always allow this many chats** (`minRunning`) — 1, от 0 до 100.

Сохранённые значения проверяются при чтении; значение вне диапазона
заменяется значением по умолчанию.

## Команда

`bb memory-gate status [--json]` — для каждой машины: показание, его возраст,
ответ для нового чата сейчас (стартует / ждёт и почему) и настройки.

## Чего плагин не может

- Работает только на Linux; на macOS и Windows все ходы идут.
- Работающий чат никогда не останавливается.
- Кнопка **Send now** по замыслу bb обходит хуки: сообщение уходит сразу.
- Память вне контейнера видна только через `MemAvailable`.
- Пока память машины не читается дольше 30 секунд, новые ходы идут без
  проверки; `bb memory-gate status` показывает это как
  `a new chat starts unchecked: no memory reading`.

## Разработка

```sh
pnpm install            # из корня репозитория
pnpm --filter bb-plugin-1ma-memory-gate run typecheck
pnpm --filter bb-plugin-1ma-memory-gate run test
pnpm --filter bb-plugin-1ma-memory-gate run build   # bb plugin build → dist/
```

Разбор файлов (`memory.ts`) и решение (`gate.ts`) — чистые функции с
тестами; связка с bb (`server.ts`) проверяется на `createFakePluginHost` из
`@get-bb/plugin-sdk/testing`, хост-часть — на
`experimental_createHostEntryHarness` из `@get-bb/plugin-sdk/testing/host`.
