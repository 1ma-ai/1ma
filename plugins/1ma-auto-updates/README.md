# 1ma Auto Updates

Серверный плагин 1ma: ставит обновления CLI провайдеров (Codex, Claude Code и
других, которыми управляет bb) и обновления плагинов, только когда ничего не
работает. Заменяет автоматизации со скриптом обновлений на каждой машине.

## Как работает

- Раз в 15 минут (`*/15 * * * *`) проверяет, что 15 минут не было ни хода, ни
  его завершения или сбоя (события `thread.active`, `thread.idle`,
  `thread.failed`), и что сейчас ничего не работает: ни один тред, включая
  скрытые и архивные, не стартует и не работает, нет фоновых агентов, фоновых
  команд и workflow. Список тредов, который не удалось прочитать, считается
  занятым. Фоновая команда может сама вызывать CLI провайдера, поэтому тоже
  считается работой.
- Собирает работу: для каждой подключённой постоянной машины — провайдеры, у
  которых bb предлагает действие `update` (новые CLI не ставит), и плагины с
  `updateState.outcome === "update-available"` по последней проверке bb.
  Плагины из репозитория 1ma (`git:https://github.com/1ma-ai/1ma…`)
  обновляются по настройке **Update 1ma plugins**, все остальные — только по
  отдельной настройке **Update plugins from other sources**, выключенной по
  умолчанию: их обновления приходят без проверки 1ma.
- Ставит обновления по одному, себя — последним. Перед каждым открывает окно:
  хук `message.dispatch` отвечает `wait` новым сообщениям (с `sendAt` через
  30 секунд, в причине — что именно ставится), через 5 секунд ещё раз
  проверяет треды и, если что-то успело начаться, закрывает окно и оставляет
  это и все следующие обновления до следующего прохода. Окно держится, пока
  идёт установка, без собственного срока: установку CLI bb сам прерывает
  через 15 минут. После каждой установки окно закрывается, и core сразу
  отправляет придержанные сообщения (`experimental_hooks.recheck`).
- Сбой одного обновления не мешает остальным; итог прохода (поставлено, не
  удалось, отложено) пишется в журнал плагина.

## Чего плагин не может

Кнопка **Send now** у придержанного сообщения по замыслу bb обходит хуки всех
плагинов: так пользователь сам решает отправить сразу. Причина ожидания
предупреждает, что такое сообщение может застать CLI недоустановленным. Все
остальные пути запуска хода (обычная отправка, Provider Retry и его
продолжение после перезапуска, сообщения между тредами) проходят через хук.

## Настройки

- **Update provider CLIs** — по умолчанию включено.
- **Update 1ma plugins** — по умолчанию включено. На Linux-сервере владельца
  выключено: плагины туда выкладывает `scripts/release-linux.mjs`, а установка
  из git собирает их вне лимита heavy.
- **Update plugins from other sources** — по умолчанию выключено.

## Разработка

```sh
pnpm install            # из корня репозитория
pnpm --filter bb-plugin-1ma-auto-updates run typecheck
pnpm --filter bb-plugin-1ma-auto-updates run test
pnpm --filter bb-plugin-1ma-auto-updates run build   # bb plugin build → dist/
```

Логика (`auto-updates.ts`) проверяется с поддельными зависимостями, связка с
bb (`server.ts`) — на `createFakePluginHost` из `@get-bb/plugin-sdk/testing`.
